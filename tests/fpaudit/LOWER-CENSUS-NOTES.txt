Lower-table census, battery 1: integer/move exact; Q-pipeline anomaly open
==========================================================================
14 lower ops x 400 cases x {default, exactdiv}, full-state diff.

Verified exact (all state, both configs):
  IADD ISUB IADDI IAND IOR  -- the integer ALU is bit-exact between
    engines (executed-effect confirmed: results land in VI)
  MOVE MR32 MTIR MFIR       -- register moves exact (MTIR effect
    confirmed, 371/400 nonzero results)

Weak rows (recorded, not claimed):
  LQI SQI ran against all-zero VU memory (the rig does not seed data
  memory; both engines read the same zeros, so agreement is real but
  coverage is trivial). Memory seeding is a rig extension for the
  next battery.

Q pipeline -- RESOLVED (this commit):
  The "lane-selection anomaly" was a rig readback artifact: the
  recompiler retires committed Q into VI[REG_Q] (microVU_Branch
  block-end flush), not the q field the readback compared, so the
  Q column was seed-vs-computed. The lane-identified probe (distinct
  exponent per lane, 16 fsf/ftf combos) then showed 16/16 bit-exact
  agreement -- no decode disagreement exists. The exec export now
  mirrors the recompiler's committed VI[REG_Q]/VI[REG_P] into the
  q/p fields so the readback slots are engine-agnostic.

  Real Q census (400 cases): default DIV 183, SQRT 106, RSQRT 184
  divergent -- one-ulp chop-vs-model plus overflow clamp-vs-saturate,
  the classes exact divide exists for; wire proven live (183/400
  def-vs-exactdiv rec deltas). Under exactdiv: DIV 0, SQRT 0,
  RSQRT 7 -- and the RSQRT residual was an ORACLE bug: every case
  was ft = -0, where the interpreter's hand-coded zero-denominator
  path XORed both signs while the hardware-verified model, the
  exact stub, and the recompiler's default emission all agree the
  sqrt stage strips the denominator sign (saturation by numerator
  sign alone). With the interpreter corrected: DIV 0, SQRT 0,
  RSQRT 0 -- the exact-divide option is bit-exact for the entire
  Q pipeline, its first accuracy verification.

Rig lessons banked this battery:
  - The q field sits at regs_io offset 656 (after the 16-byte ACC at
    640); the first analysis read 644 -- inside ACC -- and produced
    an all-zero Q column that the executed-effect check (q_out must
    differ from q_in) exposed. That check is now part of the
    standard battery integrity set alongside files-must-differ and
    known-answer splits.
